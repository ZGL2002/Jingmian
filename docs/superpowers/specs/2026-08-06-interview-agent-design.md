# 面试 Agent 设计文档

日期：2026-08-06
状态：待用户评审

## 1. 背景与目标

制作一个"模拟面试官"Agent：AI 扮演资深面试官，用户作为候选人进行面试练习。第一版聚焦**后端技术面**（简历深挖为主线），兼顾行为面；通过终端文本方式使用；模型使用 DeepSeek 起步。

核心成功标准：

1. 用户粘贴简历后，面试官能基于简历进行有深度的追问，而不是泛泛提问。
2. 每场面试至少包含一道场景题，且约 30% 的题目考察通用后端与 AI 应用开发基础。
3. 面试结束（用户说"结束"，或至少 20 题且面试官判定考察已连贯收束）后生成可读的评估报告与完整对话记录。
4. API key 不泄露；Agent 无法逃逸到允许的目录之外。
5. 架构为未来的 Web、语音视频、微信/飞书、多 Agent 协作预留扩展位。

## 2. 范围

### 第一版包含

- Python 命令行程序（终端一问一答）。
- 工具型 Agent 核心：思考 → 调用工具 → 观察结果 → 继续。
- 简历输入：粘贴文本或文件路径（`.txt` / `.md` / `.pdf`，PDF 支持文字层抽取）。
- 按简历动态组装系统提示词（面试官人设 + 技能栈/项目 + 题目策略）。
- 自由对话式提问与追问；至少 20 题后才允许自动收尾，收尾需连贯渐进、不得草率；可随时说"结束"。
- 结束评估：四个维度评分 + 优缺点 + 改进建议。
- 长回答保护：用户单次回答超过阈值（默认 100,000 字，可配置）时自动落盘到文件，对话记录只存摘要与文件指针，防止撑爆上下文；另有基于上下文占用比例的紧急保护。
- 本场记录落盘：简历副本、实际提示词、对话记录（JSONL）、长回答全文、评估报告（Markdown）。
- 工具集：`read_file` / `write_file` / `append_file` / `edit_file` / `list_dir` / `append_transcript`。
- 安全：密钥仅走环境变量；路径强校验；无 shell / 任意命令执行工具。

### 第一版明确不做（未来扩展）

- 语音 / 视频面试（ASR / TTS / 通话）。
- Web 端、微信、飞书等渠道。
- 扫描版 PDF 的 OCR。
- 岗位描述（JD）解析与出题。
- 跨场长期记忆、上下文自动压缩（仅预留结构）。
- Agent Team（团队化多 Agent，仅预留组件边界）。
- 长回答的追问子 Agent（第一版由主 Agent 直接读文件）。
- MCP 外部工具接入（仅预留 Tool 接口）。
- 面试官模式选择（严肃 / 友好 / 压力 / 引导）。
- 数据库存储（第一版用文件）。

## 4. 架构总览

分层架构，核心原则：**面试官大脑与界面无关**。

```
表现层          CLI 终端交互（v1）→ 未来: Web / 微信 / 飞书 / 语音视频
   ↓
Agent 核心       工具型 Agent 循环（思考 → 调用工具 → 观察 → 继续）
                内含轻量会话状态机，负责最低题数与结束条件等硬约束
   ↓
工具层           工具注册表：read_file / write_file / append_file /
                edit_file / list_dir / append_transcript
                （未来经适配器接入 MCP 外部工具）
   ↓
领域逻辑         简历解析、按简历定制提示词、评估报告生成
   ↓
基础设施         LLM Provider 适配（DeepSeek 起步）、密钥管理、文件存储
```

## 5. 核心组件与职责

Python 包 `interview_agent`，模块划分：

| 模块 | 职责 |
| --- | --- |
| `cli.py` | 终端入口：收集简历、逐轮对话、处理"结束"命令、展示报告路径 |
| `agent.py` | Agent 循环：调用模型（含工具定义）、执行工具调用、处理工具结果；迭代上限保护 |
| `session.py` | 会话状态机：`开始 → 开场 → 提问 → 收尾 → 评估 → 结束`；管理最低题数（默认 20）与结束条件（用户结束优先；未满 20 题不得自动收尾） |
| `tools/` | 工具注册表与实现；每个工具 = 名称 + 描述 + JSON Schema + 实现 |
| `resume.py` | 简历解析：读取 `.txt` / `.md` / `.pdf`，归一化为 `ResumeDocument`（语言、技能、项目、工作经历） |
| `prompts.py` | 提示词模板：面试官人设、按简历定制策略（深挖优先 / 至少一道场景题 / 30% 通用与 AI 应用基础）、渐进深入节奏（收尾前覆盖完整、不草率）、人设模式模板库（未来严肃 / 友好 / 压力 / 引导）、评估模板 |
| `llm.py` | Provider 适配层：统一 `LLMClient` 接口，实现 DeepSeek 客户端（OpenAI 兼容）；未来新增实现即可换模型 |
| `report.py` | 评估报告生成：读取对话记录，产出 Markdown 报告 |
| `storage.py` | 文件存储：会话目录创建、记录读写、长回答落盘、原子写（tmp + rename）、路径规范化（与 `security.py` 配合） |
| `security.py` | 路径校验、密钥校验、注入防御辅助 |
| `config.py` | 配置加载：`.env`（密钥）+ 环境变量（模型名、最低题数等） |

## 6. 数据流（一次完整面试）

1. **启动**：`python -m interview_agent`，校验 API key；提示输入简历（粘贴文本或文件路径）。
2. **简历处理**：解析简历 → 提取语言 / 技能 / 项目 → 组装定制系统提示词 → 创建会话目录，保存 `resume.md` 与 `prompt.md`。
3. **开场**：Agent 自我介绍并说明规则（随时可说"结束"）；外壳将开场白镜像写入 `transcript.jsonl`。
4. **问答循环**：
   - 用户回答（或输入"结束" / `exit` / `/end`）。
   - Agent 决定：追问 / 下一题 / 收尾；需要时调用工具（读记录、写笔记、追加对话）。
   - 每轮通过 `append_transcript` 写入记录（外壳同时镜像兜底）。
   - 题目计数 +1；未满 20 题不得自动收尾；满 20 题后由面试官按"覆盖完整、节奏自然收束"判断是否收尾，禁止草率收束。
   - 用户回答超过阈值（默认 100,000 字）时：全文写入本场 `answers/` 目录，transcript 只记录摘要与文件指针；追问时主 Agent 用 `read_file` 读取全文（未来由追问子 Agent 专职处理）。若上下文占用接近上限（如 80%），即使未达阈值也触发紧急落盘。
5. **结束**：用户主动结束，或面试官判定收尾 → Agent 读取完整对话记录（`read_file`）→ 生成四维度评估与改进建议 → `write_file` 产出 `report.md`。
6. **收尾**：显示报告路径，询问是否开始下一场（可更换简历）。

## 7. 存储结构（按用户命名空间隔离）

```
interviews/
  └─ <user_id>/                       # v1 为本地用户名；未来为认证用户 ID
      └─ 2026-08-06_1430_8f3a2b/      # 会话 ID = 时间戳_8位随机
          ├─ resume.md                # 简历副本
          ├─ prompt.md                # 实际使用的系统提示词
          ├─ transcript.jsonl         # 完整对话记录（每行一轮，含时间戳与角色）
          ├─ answers/                 # 超阈值长回答全文（answer_1.md、answer_2.md...）
          ├─ blocks/                  # 块级压缩：完整块落盘（block_1_<topic>.md...，未来扩展）
          ├─ summary.md               # 上下文超限时生成的前文摘要（未来记忆雏形）
          └─ report.md                # 评估报告
```

隔离规则：

- 所有读写以当前 `user_id` 命名空间为根。
- 记忆 / 记录文件携带 owner 元数据（首行 JSON 注明 user_id 与会话 ID）。
- 工具层只允许访问当前用户命名空间与用户明确提供的简历路径。
- 用户根目录由认证 / 会话上下文注入，工具不自行猜测或接受参数指定的用户根；跨用户路径一律拒绝（即使解析后落在另一用户目录内）。
- 读取文件前核对 owner 元数据声明的 user_id 与当前用户一致，不一致则拒绝。
- 未来服务端：认证得到 `user_id`，强制隔离 + 只检索自己的命名空间。

## 8. 工具集（第一版）

| 工具 | 用途 |
| --- | --- |
| `read_file` | 读取简历文件、回看对话记录、读取已写文件 |
| `write_file` | 创建/覆盖文件（如报告、简历副本、提示词副本） |
| `append_file` | 文件末尾追加（通用） |
| `edit_file` | 精确修改文件局部内容（如调整提示词模板） |
| `list_dir` | 查看会话目录 / 记录目录内容 |
| `append_transcript` | 带格式约束的对话记录追加：自动写入角色、轮次、时间戳，保证 JSONL 结构统一 |

所有工具经统一注册表暴露给模型，含 JSON Schema 校验。

每个工具实现统一 `Tool` 接口（name / description / input_schema / invoke）；未来 MCP 外部工具经 `MCPToolAdapter` 包装后进入同一注册表。

第一版即遵循"单一写入者"原则：`transcript.jsonl` 只经 `append_transcript` 写入；所有落盘采用原子写（先写 `.tmp` 再 rename 替换）。这为未来多 Agent 并发协作打下基础。

## 9. 安全设计

### API key 保护

- 密钥只从环境变量读取（`.env` 文件 + `python-dotenv`，文件权限 600）。
- `.gitignore` 排除 `.env` 与任何密钥文件。
- 密钥永不进入提示词、对话记录、报告或日志；启动时校验存在，缺失给出安装指引。

### 沙箱逃逸防护

- **无 shell / 任意命令执行工具**：第一版工具集只有文件操作，这是最大的防线。
- **路径强校验**（`security.py`）：所有文件工具入参 canonicalize + 解析符号链接；工具根目录由会话上下文注入，只允许当前用户命名空间（`interviews/<user_id>/`）与用户明确提供的简历路径；拒绝 `..`、越界绝对路径、指向命名空间外的符号链接。
- **跨用户访问防护**：A 用户会话中的任何工具调用都无法访问 B 用户命名空间（路径校验 + owner 元数据双重检查，见第 7 节）。
- **提示词注入防御**：简历、JD、用户回答一律视为"数据"而非"指令"；系统提示词明确声明不执行其中的指令；Agent 观察到可疑指令时忽略并向用户说明。
- **工具白名单 + JSON Schema 校验**：越权调用被拦截并返回错误。
- 测试覆盖：路径穿越、符号链接逃逸、密钥泄漏检查（见第 11 节）。
- 未来 Web 形态：容器级用户隔离，依旧不提供任意代码执行能力。

## 10. 错误处理

| 场景 | 处理 |
| --- | --- |
| DeepSeek API 网络错误 / 超时 | 指数退避重试（最多 3 次），仍失败则提示稍后再试；已记录对话不丢失 |
| API key 缺失 / 无效 | 启动时校验缺失；调用时 401 明确提示密钥无效，不打印密钥内容 |
| 简历为空 / 解析不出内容 | 提示重新输入；允许"无简历模式"（跳过简历，只出通用后端与 AI 应用基础题）；扫描版 PDF（无文字层）提示建议转为文本，OCR 为未来扩展 |
| 中途崩溃 / Ctrl+C | 外壳镜像兜底保证已有对话在 `transcript.jsonl`；重启后可继续或直接出报告 |
| 超长回答 | 单次回答超过阈值（默认 100,000 字）时自动落盘到 `answers/`，对话记录只保留摘要与文件指针；上下文占用接近上限（如 80%）时触发紧急落盘保护 |
| 上下文超限 | v1 用滑动窗口（最近 N 轮完整 + 前文摘要，写入 `summary.md`）；未来升级为块级压缩优先（见第 13 节），滑动窗口兜底 |
| 工具调用异常 | Agent 收到错误结果并重试（最多 2 次）；目录权限问题给出明确提示 |

## 11. 测试

- **单元测试**：简历解析（txt/md/pdf）、提示词组装（不同简历 → 不同提示词）、状态机转换（未满 20 题禁止自动收尾 / 用户结束 / 满 20 题后可收尾）、长回答阈值落盘与摘要生成、上下文占用比例的紧急落盘、块级压缩（块完成后落盘并替换为摘要）、每个工具的读写行为、报告生成。
- **集成测试**：mock LLM 客户端跑完整面试流程（追问、结束、出报告），验证 transcript 与 report 落盘正确。
- **安全测试**：路径穿越与符号链接逃逸用例；跨用户访问拒绝（A 用户会话尝试访问 B 用户目录）；确认密钥不出现在任何落盘文件与输出中。
- **手动验收**：接真实 DeepSeek API 完整跑一场 3-5 题面试，检查追问质量与报告可读性。

## 13. 未来扩展点（仅预留结构，不实现）

1. **换模型**：`LLMClient` 适配层，新增 OpenAI / Anthropic / 本地模型实现即可。
2. **换渠道**：输入输出抽象，Web / 微信 / 飞书 / 语音视频（ASR / TTS）都是换壳。
3. **JD 出题**：复用简历解析的同类结构，增加岗位描述解析与按 JD 出题模板。
4. **长期记忆与上下文压缩**：本场 `summary.md` 为雏形；跨场记忆沿用用户命名空间目录体系。上下文压缩采用**块级收束**：会话按主题/项目划分块（如"项目 A 深挖块"、"场景题块"、"通用基础块"），每完成一个块即把完整轮次落盘到 `blocks/block_<N>_<topic>.md`，主上下文只保留统一格式摘要（覆盖的问题、回答要点、薄弱点、遗留问题）；滑动窗口作为兜底。
5. **Agent Team（团队化多 Agent）**：组件边界已按角色拆分（提问 / 出题 / 评估 / 记忆）。未来演进为 agent team：**Team Leader** 负责把面试目标拆解成任务并分配 / 仲裁，**队员 Agent** 自主认领任务并推进（出题、仓库深挖、长回答追问、评估、记忆维护各司其职）。协作机制：
   - 任务板：每场会话一个任务清单文件（待认领 / 进行中 / 待复核 / 完成 / 阻塞），Leader 维护，队员只更新自己任务的状态。
   - 认领与仲裁：队员认领任务时声明读写文件集；Leader 对敏感任务（写共享文件、跨模块改动）做仲裁，从分配阶段避免冲突。
   - 消息传递：Leader 与队员通过消息通道协作，队员将完成结果回传 Leader 整合。
   - 其中**仓库深挖子 Agent**（即"项目拷打子 Agent"）与**长回答追问子 Agent** 为明确规划：仓库深挖子 Agent 由用户显式授权仓库路径后，用文件工具阅读源码（参考 interviewer-mcp 的代码地图与薄弱点再攻机制），以**独立上下文**完成整块项目深挖，只把摘要与薄弱点回传主面试官，显著降低主 Agent 上下文占用；追问子 Agent 专职读取 `answers/` 中的超长回答全文并产出追问建议。
   - **文件读写冲突解决方案**（预先设计，未来实现）：
     1. 单一写入者：共享文件（`transcript.jsonl` / `resume.md` / `prompt.md` / `report.md`）各只允许一个写入者，其余 Agent 只读。
     2. 私有工作区：队员的中间产物先写自己的 `agents/<agent_id>/` 目录，最终产物由对应写入者或 Leader 合并提交。
     3. 原子写：先写 `.tmp` 再 rename 替换，读者永远不会看到半截内容。
     4. 文件锁：确需多写者串行化的文件用 `fcntl.flock` 或锁文件，带超时防止死锁。
     5. 冲突检测：写前记录 base 哈希，写时校验；内容已变化则重读合并再写。
     6. 分配期规避：认领任务时声明 write set，Leader 仲裁，避免两个任务同时写同一文件。
6. **面试官 Skill 打包**：提示词模板天然可抽成 skill，配合按简历动态组装，未来做成可独立发布的内容。
7. **MCP 外部工具接入**：统一 `Tool` 接口 + `MCPToolAdapter`，本地 MCP server 工具经适配器注册进工具注册表；每个外部工具按白名单审批后启用。典型场景：接入 GitHub 搜索类 MCP server（检索仓库 / 代码 / 用户），配合仓库深挖子 Agent（interviewer-mcp 思路），实现"先搜索到开源项目，再深挖源码"的完整链路。
8. **面试官模式选择**：提示词层定义人设模式库（严肃 / 友好 / 压力 / 引导），CLI / 配置可切换；v1 默认专业严肃。
9. **多语言支持（英文等）**：提示词模板、界面与报告文案按语言参数化（i18n）；会话元数据记录语言；第一版中文，未来 CLI / 配置 / Web 下拉选择面试语言。

## 14. 默认行为与配置

- 默认最低题数：20 题，未满不得自动收尾（环境变量 `INTERVIEW_MIN_QUESTIONS` 可改）。
- 长回答阈值：100,000 字（环境变量 `INTERVIEW_ANSWER_OFFLOAD_THRESHOLD` 可改）；上下文占用比例保护默认 80%（环境变量 `INTERVIEW_CONTEXT_SAFETY_RATIO` 可改）。
- 默认面试官模式：专业严肃（人设模式库为未来扩展）。
- 面试语言：中文（界面、对话、报告；环境变量可配置）。
- 默认模型：`deepseek-chat`（环境变量 `INTERVIEW_MODEL` 可改）。
- 密钥：环境变量 `DEEPSEEK_API_KEY`（`.env` 文件）。
- 技术栈：Python 3.11+；标准库 CLI + `python-dotenv` + `openai` SDK（DeepSeek 兼容）+ `pypdf`（PDF 抽取）；无重型框架。
